# Cocolon領域別: 特に壊してはいけないもの

revision_date: 2026-08-25
normative_status: CURRENT_AREA_REFERENCE

## 全体

- Cocolonは「感情入力」を中心に回る商品。
- 三大中核構造は、EmlisAI / 分析構造 / Piece構造。
- RN=表示、API=処理、DB=倉庫という国家システムの分離を崩さない。
- Free / Plus / Premium の権限制御、履歴表示期間、IAP契約を壊さない。
- 名称移行中の旧名称は、互換・DB境界・runtime ownerとして残る場合がある。

## EmlisAI

- EmlisAIはテンプレ共感文ではない。
- ユーザーの入力を読んだと感じられる最初の返答である。
- `Emlisです。` の名乗りは基本維持。
- ユーザー名 + さんの扱いを壊さない。
- 入力量に応じて返答量を調整する。
- 「強度表示」は見せない方向。
- 例文特化コードをruntimeに入れない。
- EmlisAI / CMEEのcurrent/future language routeはproviderless Route A exact1だけとする。外部生成AI、external composer、remote model/provider、current input本文またはsemantic projectionの外部送信、network call、provider dependency、fallback、external costを追加・復活させない。Route Aのceilingまたはreturn budget exhaustionではそのままSTOPする。
- `observation_status=passed` と本文表示条件など、RN表示contractを壊さない。

## Piece

current product definition:

- PieceはQ&Aそのものではない。
- Q&AはPieceの一形式である。
- Pieceは、ユーザーの考えや価値観を他者に伝えるための文章へ整形し、画像化する機能である。
- Pieceを短縮要約へ潰さない。

current owner:

- `Cocolon_Piece/00_read_first.md`
- `Cocolon_Piece/manifest.json`

compatibility boundary:

- 現在のQ&A preview / draft / publish / Nexus / quota等の実装は、Piece全体のidentityではなく既存formatとcompatibility基盤として扱う。
- existing Q&A route / field / storage / recordを、actual contractと移行設計なしに削除・一括変換しない。
- 既存Q&A formatの低情報処理を、current actual file確認なしに一般Piece仕様または廃止対象へ読み替えない。
- 画像化、visual recipe、format、visibility、export等を、実装確認なしに実装済みと扱わない。
- 表示順・フォロー・共鳴・削除権限、自分のPieceとフォロー中ユーザーのPieceの境界を壊さない。

## 分析 / こころ天気

- 診断ではなく観測として扱う。
- 医療・メンタル診断に寄せない。
- 未来予測として断定しない。
- UI表示名・タブ名の変更は、関係画面・履歴画面・導線の整合を確認する。
- 入力後に最新状態で見えるか、cache / refresh / invalidationを確認する。

## チュートリアル

- チュートリアル専用の別製品を作らない。
- 実際に生成する → 保存する → 実際の画面で表示する。
- 実生成していない文章を、生成済みデータのように固定しない。
- 既存UIと同じ性能・同じ見え方にする。

## サブスク / IAP

- Free / Plus / Premium の文言と権限制御を混同しない。
- 無料トライアル概念は消す方針。
- iOS / Android SKUの違いを混同しない。
- 期限切れ時のFree戻し、cancelled / grace / activeのexpires_at判定を壊さない。

## DB / API / legacy

- DB physical rename / dropは明示指示なしにしない。
- legacy route削除は明示指示なしにしない。
- bridge view / read-only / write pathの境界を崩さない。
- response key変更はRN破壊につながるため、明示指示なしにしない。
