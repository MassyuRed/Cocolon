# Cocolon領域別: 特に壊してはいけないもの

revision_date: 2026-08-07
normative_status: CURRENT_REFERENCE
active_gate_owner: 00_read_first.txt

このファイルは領域別referenceです。全体のactive Gateは`00_read_first.txt`を正とします。

## 全体

- Cocolonは「感情入力」を中心に回る商品。
- 三大中核構造は、EmlisAI / 分析構造 / Piece構造。
- RN=表示、API=処理、DB=倉庫という国家システムの分離を崩さない。
- Free / Plus / Premium の権限制御、履歴表示期間、IAP契約を壊さない。
- 名称移行中の旧名称は、互換・DB境界・runtime ownerとして残る場合がある。

## EmlisAI

- EmlisAIはテンプレ共感文ではない。
- ユーザーの入力を読んだと感じられる最初の返答である。
- `Emlisです。` の名乗りは基本維持。
- ユーザー名 + さんの扱いを壊さない。
- 入力量に応じて返答量を調整する。
- 「強度表示」は見せない方向。
- 例文特化コードをruntimeに入れない。
- 外部AIレンタル前提を勝手に復活させない。
- `observation_status=passed` と本文表示条件など、RN表示contractを壊さない。

## Piece

- PieceはQ&Aそのものではない。Q&AはPieceの一形式。
- Pieceは、ユーザーの考えや価値観を他者に伝えるための文章に整形し、画像化する機能。
- current Q&A実装はcompatibility基盤かつ一形式として扱い、Piece全体のidentityに固定しない。
- 低情報入力の扱い、表示順、フォロー、共鳴、削除権限など既存contractを、明示設計なしに壊さない。
- 自分のPieceとフォロー中ユーザーのPieceの扱いを混同しない。
- current Pieceの正本は`Cocolon_Piece/00_read_first.md`と`Cocolon_Piece/manifest.json`。

## 分析 / こころ天気

- 診断ではなく観測として扱う。
- 医療・メンタル診断に寄せない。
- 未来予測として断定しない。
- UI表示名・タブ名の変更は、関係画面・履歴画面・導線の整合を確認する。
- 入力後に最新状態で見えるか、cache / refresh / invalidationを確認する。

## チュートリアル

- チュートリアル専用の別製品を作らない。
- 実際に生成する → 保存する → 実際の画面で表示する。
- 実生成していない文章を、生成済みデータのように固定しない。
- 既存UIと同じ性能・同じ見え方にする。

## サブスク / IAP

- Free / Plus / Premium の文言と権限制御を混同しない。
- 無料トライアル概念は消す方針。
- iOS / Android SKUの違いを混同しない。
- 期限切れ時のFree戻し、cancelled / grace / activeのexpires_at判定を壊さない。

## DB / API / legacy

- DB physical rename / dropは明示指示なしにしない。
- legacy route削除は明示指示なしにしない。
- bridge view / read-only / write pathの境界を崩さない。
- response key変更はRN破壊につながるため、明示指示なしにしない。
