## bounded mechanical repair / no-retry boundary

bounded mechanical repairは、prior authorityを閉じた後のnew Mash-approved authority
exact1だけで使用します。同authority retryではありません。

current G4-Bは、同じhelper API / runtime type blocker familyのsecond failureにより
`DETOUR_RISK_STOP`へ到達し、helper routeがretiredです。したがって以下の一般mechanical
repair sequenceはcurrent G4-Bへ適用せず、helper repair、second method repair、third normal
authorityを0にします。direct native routeのfuture preflight failureにもrepairを追加しません。

対象は`SYNTAX_ERROR`、`API_ARGUMENT_ERROR`、`SERIALIZATION_FORMAT_ERROR`、
`COMMAND_CONSTRUCTION_ERROR`のexact4です。

次の全条件を満たします。

- helperまたはlauncher exact1だけを修正する。
- same Gate / purpose / contractを維持する。
- semantics、test意味、acceptance、production、protected test、fixture、sample、
  target、denominator、comparator、input identityを変更しない。
- dependency projection、network route / count、runtime roleを変更しない。
- prior authority、root、wheel、helper、readinessを再利用しない。

許可sequence:

```text
new authority exact1
-> repair exact1
-> pre-freeze preflight
-> fully fresh root / wheel / helper
-> same Gate fresh rerun exact1
-> success or STOP
```

fresh rerunはretry例外ではありません。new authorityとfully fresh artifactsを持つ
別operationです。second failureではrepair / rerun / fallbackを追加しません。
