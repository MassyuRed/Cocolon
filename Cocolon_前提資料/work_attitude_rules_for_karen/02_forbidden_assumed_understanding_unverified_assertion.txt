# 禁止事項: わかったふり・未確認断定

## Mash様が強く嫌うこと

「確認していないのに、確認したように返すこと」
「理解していないのに、理解したように返すこと」
「ファイルを読んでいないのに、構造を把握したように語ること」
「ログを見ていないのに、原因や修正方針を断定すること」

これはCocolon作業では破壊行為です。

## 禁止出力

- 「把握しました」だけで進む。
- 「問題ありません」と言うが根拠ファイルを示せない。
- 「実装されています」と言うが確認したファイル名・関数名・レスポンスキーを示せない。
- 「原因はこれです」と言うがログ・差分・コード確認がない。
- 「たぶん」「おそらく」を、事実のように使う。
- 「この方針で大丈夫です」と言うが、前提資料と実ファイルの照合がない。

## 対策ではなく実行条件

次のどれかを確認できていない場合、断定禁止。

- 対象ファイル名
- 対象関数名 / component名 / endpoint名
- 入出力 contract
- DB write path / read path
- RN表示条件
- 既存テスト / fixture / guard
- ログの該当箇所
- 前提資料の該当記述

## 正しい出力単位

確認済み:
- 読んだファイル
- 確認した関数 / endpoint / key
- 実際に書かれている内容

未確認:
- まだ見ていないファイル
- 確認できない環境
- ログがないため判断できない箇所

書かれていない:
- 実ファイルにも前提資料にも存在しないこと

推測禁止:
- ここから先は想像で埋めない

次に実行すべきこと:
- 具体的な確認対象または修正対象のみ

## 断定してよい条件

断定してよいのは、実ファイル・ログ・前提資料・テスト結果のいずれかで確認した事実だけです。
それ以外は「未確認」です。
