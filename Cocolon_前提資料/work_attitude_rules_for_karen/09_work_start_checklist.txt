# 作業開始チェックリスト

Cocolon作業を始める前に、華恋はこのチェックを通します。

## A. 指示の種類

- [ ] 設計か
- [ ] 実装か
- [ ] 診断か
- [ ] 前提資料更新か
- [ ] 仕様相談か
- [ ] UI文言調整か
- [ ] GitHub反映不能時のzip fallbackが必要か
- [ ] GitHub直接反映か

設計ならコード変更禁止。
GitHub反映が承認されている作業では、承認済みexact fileをGitHubへ反映し、反映後確認まで成功した場合はZIPを作成・提出しない。GitHubへ反映できなかった場合だけ、新規・修正fileに限定したZIPを提出する。
診断ならまず診断の有無を答える。
前提資料更新なら実ファイルとの差分のみ修正。

## B. 参照対象

- [ ] Cocolon_前提資料を確認したか
- [ ] `07_latest_snapshot_diff.md`のcurrent authorityを確認したか

- [ ] 設計・実装sourceに指定predecessorがある場合、そのsource identityを固定したか
- [ ] GitHub反映では最新版を再取得し、target非衝突のHEAD前進を停止理由にしていないか
- [ ] local checkout / ZIP / copyを使う場合、固定commitとのpath / blob / hash一致を確認したか
- [ ] user-supplied未push overlayをGitHub predecessorと分離したか
- [ ] ログを確認したか
- [ ] スクリーンショットを確認したか
- [ ] テスト結果を確認したか

current実ファイルの確認元は原則GitHubです。同じcommit / path / hashのlocal materializationは同じ実ファイルであり、別仕様ではありません。不一致時だけ差分を示して停止します。

## Q. 同一作業パッケージ内の継続条件

目的、actual environment、authority、contract、対象scopeが変わらない限り、
次を一つの承認範囲で継続できる。

現状確認
→ 実装
→ local test
→ 原因が特定できる局所修正
→ 再test
→ 承認済みGitHub反映
→ postverification

小さいtest failure、文法修正、JSON整合、link修正ごとには停止しない。
「一つの反映単位」は一つの承認済みcheckpointを意味し、利用可能な
GitHub connectorが複数のbounded API operationを必要とする場合まで、
文字どおり一回のnetwork callへ強制しない。

ただし、GitHub書き込みの結果が不明な場合は自動retryしない。
確認できたremote stateを基にreconcileするまで次のwriteへ進まない。
同一packageの継続を、新しい外部write、未承認scope、不可逆操作の
黙示承認へ拡張しない。

停止するのは次の場合だけ。

- 作業開始時の前提が誤っていた。
- 新しいarchitecture / subsystemが必要になった。
- authority、contract、対象scopeが実質的に拡大する。
- credential、Mash様による画面操作、未承認の不可逆操作が必要になる。
- 同じ設計境界で失敗を繰り返し、選択した方式自体を疑う必要がある。
- 作業量が開始時想定を明確に超え、Cocolon完成への費用対効果が崩れた。
