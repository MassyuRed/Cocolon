revision_date: 2026-08-07

このchecklistは、全ruleの再掲ではありません。
今回の作業で必要なrule、source、authority、durable ownerを実際に選び、開始可否を判定するGateです。
一つでも必要項目が未成立なら、その項目に依存する作業を開始しません。

## A. Model / environment

- [ ] 実際のChat modelが`GPT-5.6 Pro`と確認できる。
- [ ] non-Proまたはmodel不明の成果物を採用していない。
- [ ] 今回のbounded作業単位を`CHAT_5_6_PRO_OK` / `WORK_ULTRA_REQUIRED`で判定した。
- [ ] Work不可を理由に品質条件を弱めていない。

不成立時:
`MODEL_OR_ENVIRONMENT_NOT_ELIGIBLE_STOP`

## B. 目的・指示・完了条件

- [ ] 今回の作業がCocolon完成のどの条件へ接続するか説明できる。
- [ ] 指示種別を特定した。
- [ ] 成果物、対象scope、非対象scopeを特定した。
- [ ] 完了条件と停止条件を特定した。
- [ ] 不足情報を隠すための代替作業を発明していない。

- [ ] 対象前提資料とactual file / contract / test / logを確認した。
- [ ] 指定predecessor、local materialization、未push overlayを分離した。

## D. authority / effect

- [ ] current authority ownerとlifecycleを特定した。
- [ ] proposal / approved / activated / admitted / consumed / PASS / STOP / closed / creditを分けた。

- [ ] `position_change_effect`の有無を判定した。

## F. Mash様への質問・依頼

質問または操作依頼を出す場合だけcheckする。

- [ ] file / GitHub / code / log / connectorで華恋が解決できない。
- [ ] 既出設計を再質問していない。
- [ ] Mash様にしか決められない思想・構想または操作である。
- [ ] 内部設計用語を平易な人間の言葉へ翻訳した。
- [ ] 操作依頼では、原因、必要性、代替不能理由、端末、開始画面、手順、禁止事項、完了条件、華恋が引き取る範囲を示す。
- [ ] 選択肢を投げず、推奨手順を一つ選んだ。

## G. product / contract non-break

- [ ] RN表示、API、DB write、access、subscription、account delete、user data protectionへの影響を確認した。
- [ ] DB physical name、legacy façade、route、response keyを勝手に変えない。
- [ ] fixture / test greenだけで商品品質合格としない。
- [ ] current product definitionと過去構想を分けた。

## H. artifact / GitHub / continuity

- [ ] material artifactのdurable ownerを特定した。
- [ ] GitHub writeがMash様の承認scope内か確認した。
- [ ] 承認がない場合、local-only完成扱いをせず`DURABLE_WRITE_APPROVAL_REQUIRED`で止める。
- [ ] write前のlatest head / target path / preimageを確認する。
- [ ] write後のremote bytes / changed paths / final headを確認する。
- [ ] secret / body-full private evidenceをpublic GitHubへ出さない。
