# 禁止事項: 前提資料と実ファイル確認不足

## 固定ルール

Cocolon作業では、Cocolon_前提資料を読まずに出力してはいけません。
ただし、前提資料だけで「理解している風」に返してもいけません。
前提資料は地図であり、実ファイルが現物です。

## 必ず確認するもの

作業内容に応じて、次を確認します。

- `Cocolon_前提資料/00_karen_read_first.md`
- `03_cocolon_naming_system.md`
- `09_Cocolon_名称混在保管と構造境界_YYYY-MM-DD.md`
- `01_cocolon_overall_structure.md` 系
- `02_cocolon_national_system.md` 系
- `05_cocolon_rule_file_index.md`
- `07_latest_snapshot_diff.md`
- GitHub上の`Cocolon` / `mashos-api` current head、固定predecessor commit、対象実ファイル
- local checkout / ZIP / copyを使う場合、そのpath / blob / hashが固定GitHub commitと一致すること
- 必要なログ / スクリーンショット / テスト結果

## 前提資料の読み方

前提資料は、タスク表ではありません。
前提資料は、Cocolonのファイル構成・コード構成・名称混在境界を復元するための作業用地図です。

旧名称が残っていても、すぐrenameしません。
旧名称には、互換・DB境界・runtime owner・legacy façadeとして残す理由がある場合があります。

## 禁止事項

- 前提資料を読まずにCocolon構造を語る。
- 前提資料だけ読んで、実ファイルを見ずに修正判断する。
- 旧名称を見つけて即renameする。
- DB physical name、legacy route、response key、RN表示条件を勝手に変える。
- Cocolon_前提資料を残タスク表として扱う。
- Cocolon_前提資料更新時に、変更がない箇所まで触る。

## 正しい処理

1. 前提資料で「地図」を見る。
2. 最新実ファイルで「現物」を見る。
3. 両方に差分があれば、差分として扱う。
4. 書かれていなければ「書かれていない」と言う。
5. 指示がない限り、仮説で補完しない。

## Cocolon_前提資料更新時のルール

- 原則としてGitHub上の`Cocolon` / `mashos-api`をcurrent実ファイル確認元にし、作業開始時にpredecessor commitを固定する。
- GitHubからmaterializeしたlocal checkout / ZIP / copyは、path / hash一致時に同じ実ファイルとして扱う。local / cloud差を別仕様にしない。
- user-supplied未push overlayがある場合はhandoff materialとして分離し、固定GitHub predecessorを黙って置換しない。
- GitHubとlocal materializationが不一致なら同一視せず、commit / path / hash差を提示して停止する。
- 過去local ZIPのsnapshot名・hash・countは当時の証拠として残し、current GitHub値へ遡及上書きしない。
- 前提資料との差分だけを見る。
- 変更点がない資料は触らない。
- 修正必要箇所のみ差分修正・差分追記する。
- 修正したファイルのみzipで渡す。
- 作業報告や残タスクを前提資料に混ぜない。
