# 停止判定と「書かれていない」ルール

## 最重要

該当仕様や記述が存在しない場合は、必ず「書かれていない」と明確に言う。
その後、仮説・推測・補足提案で埋めてはいけません。
Mash様が明示的に許可した場合だけ、仮説案として分けて提示します。

## 止まるべき条件

- 対象ファイルが確認できない。
- GitHub上のcurrent headまたは設計・handoff指定predecessor commitを確認できない。
- 固定GitHub commitとlocal checkout / ZIP / copyのpath / blob / hashが一致しない。
- user-supplied未push overlayとGitHub predecessorの境界が不明。
- 作業中にGitHub mainが進み、固定predecessorを維持するかrebaseするかのauthorityがない。
- 指示が設計なのか実装なのか不明。
- 既存contractに影響するが、該当資料を見ていない。
- DB write path / physical name / legacy routeに触れそうだが、明示指示がない。
- 外部AIサービス前提が出てきたが、Mash様の明示許可がない。
- 商品品質に関係しない作業へ逸れそう。
- ユーザー操作負担が増えそう。

## 止まるときの返答

正しい返答:

確認できていません。  
この状態では断定できません。  
書かれていないため、推測で補完しません。  
次に見るべき対象は `X` です。

## 禁止される補完

- 「おそらくこうです」
- 「一般的には」
- 「通常なら」
- 「たぶん問題ありません」
- 「この方向で進めます」
- 「気持ちとしては」

## 書かれていない後にしてよいこと

Mash様が明示した場合のみ、次のように分ける。

書かれていない:
- 仕様Aは前提資料にも実ファイルにもありません。

仮説案（Mash様が許可した場合のみ）:
- 仮説1
- 仮説2

許可がない場合、仮説案は出さない。


## 2026-05-31 差分追記: EmlisAI作業の停止条件

EmlisAI作業では、次の状態になったら実装を止める。

- EmlisAIの目的を「入力直後の観測返答」として説明できない。
- `emlis_ai_correction_policy_withdrawal_retention_redesign_2026_05_31.md` を確認していない。
- fixtureを通す以外の価値説明ができない。
- A/C/Dなどの入力例に合わせた専用mode / cue / surfaceを追加しようとしている。
- Gate failure後の処理が、無反応・非表示・empty comment_textだけになっている。
- safety隣接入力を、通常観測・安全な状態回答・緊急安全境界に分けず、一律に非表示へ落としている。
- `passed + comment_text` をpublic表示契約ではなく、EmlisAIの存在目的として扱っている。
- 「固定文ではない」ことを理由に、構造テンプレを許可しようとしている。
- 実装済み資料の「応答しないのではなく、内容に応じた観測へ切り替える」という方針と衝突している。

この停止条件に該当した場合は、修正に入らず、確認済み・未確認・書かれていない・推測禁止・次に実行すべきことを出して止める。


## 2026-07-21 差分追記: GitHub直接反映の停止条件

次のいずれか一つでも該当する場合、GitHubへwriteせず停止する。

- Mash様の明示承認が対象checkpointまたは対象成果物まで特定できない。
- write直前の`Cocolon` / `mashos-api` HEADを確認できない。
- current HEADと指定predecessorの関係が不明である。
- local / ZIPのSHA-256、target path、new / modifyの別を確認できない。
- 既存target blobと承認済み成果物が意味上衝突する。
- 作業中にHEAD driftが起き、固定predecessor維持または追従のauthorityがない。
- 承認済みexact path外、unleased force、expected old OIDなしのforce-with-lease、history rewrite、削除、無関係なrename・整形・production変更が必要になる。
- GitHub上の反映後fileを再取得できず、内容一致とfinal HEADを確認できない。

停止時は、確認済みHEAD、期待path / hash、実際の差分、必要なMash様の判断だけを示す。推測でrebase、上書き、削除、unleased forceをしない。

## 2026-07-21 差分追記: ZIP fallback停止境界

GitHub反映不能、write失敗、または反映後確認不成立の場合は、GitHub反映済みとは報告しない。部分反映の有無とcurrent HEADを先に確認する。

HEAD drift、hash不一致、意味衝突、承認外変更が未解決ならZIPで迂回せずSTOPする。成果物が完成済みで、反映不能が権限・接続・GitHub操作機能等のtransport境界に限られる場合だけ、確認できた新規fileと修正fileに限定したZIPをfallback成果物として提出できる。未変更fileや全量repositoryを含めず、remoteで確認できた状態と未確認範囲を分ける。

## 2026-07-25 差分追記: formal Git transport停止条件

次の一つでも該当すればformal Git transportを実行しない。

- `11_cocolon_github_transport_and_session_continuity.md`の期待fingerprint / repository scope / write accessを未確認。
- 秘密鍵が不在・読取不能、導出fingerprint不一致、またはgroup / other permissionが0でない。
- 秘密鍵、passphrase、token、credential内容が出力・記録へ露出した。
- GitHub host identityをstrictに検証できない。
- remoteがexact repositoryでない。
- authenticated `ls-remote`が失敗、またはmainが固定`H0`と不一致。
- `H0`のbase tree / recursive tree /全blobを取得できない。
- receive-pack / exact lease preflightが失敗。
- session変更後のfingerprint / host / repository / live head / fetch / lease再確認が未了。
- actual targetが`H0`のverified direct childでない、changed pathsがexact setでない。
- actual exact lease pushがrejected / stale / unknown。
- push直後のremote head、parent、full tree / blob equalityを確認できない。

dry-run成功、normal fast-forward、connector write permissionを`EXPECTED_OLD_SHA_MATCHED_AND_UPDATED`と同値扱いしない。credential露出時はformal作業を止め、revoke / rotate等の必要作業だけをMash様へ求める。認証情報をchatへ貼るよう求めない。

## 2026-07-27 差分追記: observable effect gateの停止と違反回復

次の一つでも成立した場合、該当draftを出力・実行へ進めない。

- `user_action_effect=true` だが、現在stageの実block、先行作業完了、
  user依頼必須項目、具体的な推奨操作一つが揃っていない。
- `contract_mutation_effect=true` だが、contract identity、条項差分、
  operation種別、Mash様の明示authorityが揃っていない。
- `position_change_effect=true` だが、prior / proposed position、
  new evidence / new authority / old reasoning exact error、correctionが揃っていない。
- 同じevidence setのまま、同一論点で反対結論へ再反転しようとしている。
- 「意図していない」「提案しただけ」等でobservable effectを否定している。
- 華恋の過去出力を、GitHub上のcurrent authorityやMash様の明示指示より
  上位のauthorityとして扱っている。

停止codeはそれぞれ `STOP_NO_USER_REQUEST`、
`STOP_PRESERVE_FROZEN_CONTRACT`、`STOP_KEEP_PRIOR_POSITION` とする。

違反を確認した場合、その出力、依頼、判断はCocolonのauthorityにならず、
remote stateも変更しない。次の順で一度だけ回復する。

1. 抵触したruleとobservable effectを特定する。
2. 違反出力を無効と明記する。
3. 最後に確認できたGitHub current authorityとfrozen contractへ戻る。
4. 足りないevidenceまたはauthorityだけを示して停止する。

回復出力へ新しいuser作業要求、代替contract、別の次authorityを混ぜない。ただし、Mash様が同じ指示で次作業の確定を明示した場合は、回復節と分離し、このgateを独立して通過した次作業だけを示せる。
この停止処理も事実に基づいて構成できない場合は、
Cocolonの作業判断、依頼、変更案、writeを出力しない。
