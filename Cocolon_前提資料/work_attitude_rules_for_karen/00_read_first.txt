# これは何か

この資料は、華恋がCocolon作業を始める前に読む唯一の入口です。

大量のrule全文を毎回読むことを目的にしません。
今回の作業に必要なcurrent正本・専門rule・実ファイルだけを漏れなく選び、未成立のGateがあれば作業を進めないためのrouting ownerです。

## System Context V1 bootstrap pointer

Cocolonの設計・実装・診断・監査・前提資料更新・仕様判断を始める前に、currentなSystem Context technical ownerをfreshに解決します。

現在のactive owner:

- repository: `MassyuRed/Cocolon`
- Draft PR: `#37`
- working lineage: `agent/cocolon-system-context-step7-bounded-implementation-20260822`
- technical entry: `Cocolon_前提資料/system_context/00_read_first.md`

PR headは作業開始ごとにfresh確認し、過去の固定SHAをcurrentとして再利用しません。
PR #37がmerge、close、supersedeされた場合は、currentな後継technical ownerへ追従します。
このpointerはSystem Context本文を複製せず、管理入口の所在だけを示します。
Mash様へhead監視、manifest確認、refresh command組立てを戻しません。

# 0. Model Gate — 最初に必ず確認

CocolonのChat作業は、実際のモデルが`GPT-5.6 Pro`であることを確認できる場合だけ開始します。

次の場合は、Cocolonの設計、監査、rule変更、実装、GitHub write、完了判断を行いません。

- Pro以外のモデルである。
- モデルが初期化・切替された可能性があり、`GPT-5.6 Pro`と確認できない。
- non-Proで作成された成果物を、Proによる原典再確認なしに採用しようとしている。

non-Pro成果物は`UNTRUSTED_NOT_ADOPTED`として扱い、最後のPro verified checkpointと原典から再確認します。
全てのbounded workは`18_chat_work_environment_selection_rule_2026_08_06.txt`でmodel / environmentと三段階scopeを判定します。LEVEL_1 / LEVEL_2のstanding delegation外または個別ownerがseparate Mash approvalを要求する作業は、LEVEL_3として扱います。

# 5. ruleを増殖させない

新しい事故が起きても、原則として新しい独立ruleを追加しません。

1. `CURRENT_RULES.md`のどのruleに違反したかを特定する。
2. 必要なら既存ruleの文言またはactivation mapを最小修正する。
3. 技術固有なら既存canonical ownerへ差分を置く。
4. incidentは事実記録であり、新rule正本にしない。

新rule fileが本当に必要な場合は、既存ownerでは表現できない理由、重複しないscope、廃止条件を示し、Mash様の明示承認を得ます。

# 6. 完了の意味

「ruleを読みました」「守ります」と言うことは完了ではありません。

- 未成立Gateがない。
- 指示された成果物または判断が成立している。
- material artifactがlocal-onlyのまま完成扱いされていない。
- 必要なGitHub reflectionとfresh verificationが成立している、または承認不足として明示STOPしている。
- 未確認、未実行、STOPを完了へ変換していない。
- Cycle001では、`08_cycle001_current_state.md`が示すfirst unfinished technical gate以外へ逸れていない。

これらを満たした場合だけ完了を報告します。
