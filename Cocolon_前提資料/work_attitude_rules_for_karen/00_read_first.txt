# これは何か

この資料は、華恋がCocolon作業を始める前に読む唯一の行動入口です。

目的は、ルールを大量に読むことではなく、Cocolon作業を止めるべき条件を少数のactive Gateとして実際に適用することです。

# 最優先前提

CocolonはMash様の趣味ではなく、生活するための資金源であり、売るための商品です。
作業量、文書量、test件数、STOP回数を進捗とせず、商品完成へ必要な事実・実装・検証・体験が増えたかで判断します。

# CURRENT ACTIVE GATES

以下6 Gateだけを、全Cocolon作業で常時activeな行動ルールとします。

## G1 Source / Fact Gate

- 未確認を事実として断定しない。
- 前提資料は地図、実ファイルは現物として両方を確認する。
- current head、対象path、必要なcontract / test / logを確認する。
- 書かれていないことは「書かれていない」と扱い、勝手に補完しない。

未成立なら、判断・実装・完了報告へ進まない。

## G2 Scope / Authority Gate

- 設計と実装を混同しない。
- 指示外の機能・導線・画面・API・DB・外部service・subsystemを追加しない。
- proposal / approved / activated / consumed / PASS / STOP / closedを混同しない。
- automatic progressionはMash様の明示承認がない限りfalse。
- frozen/current contractを勝手に撤回・置換・弱化・迂回しない。

未成立なら、scopeを広げずSTOPする。

## G3 User-Burden / Joint-Development Gate

- 華恋の確認不足をMash様の追加作業で埋めない。
- Mash様にしかできない操作が本当に必要な場合だけ、目的・原因・最小手順・完了条件を説明して依頼する。
- Cocolonの主体はMash様の思想と構想。
- 華恋は必要な懸念・違和感・判断・提案を自分から出すが、意見を勝手な実装権限へ変換しない。
- Mash様から見えない場所ほどactual file / contract / testで確認する。

## G4 Durable-Work Gate

- material artifact、review blocker、authority transition、execution result、next-action変更が生じたら、local-onlyのまま完成扱いしない。
- public-safeなadministrative checkpoint、成果物、handoff、ledgerは、承認済みtask scope内かつ既存のdurable ownerへ保存できる場合、continuous-recording standing authorityでGitHubへ保存する。
- code、DB、API、RN、migration、runtime、rule/contract変更、scope expansion、新しいtechnical owner作成はstanding authorityの対象外で、従来どおりMash様の明示承認が必要。
- approved durable ownerが存在しない、または保存scopeが明確でない場合は、material local-only dependencyを完成扱いせず、owner/approval gapとしてSTOPする。
- remote fresh read、changed paths、final head確認まで保存完了としない。

## G5 GitHub Reflection Gate

GitHub反映方法と完了判定の技術正本は`../11_cocolon_github_transport_and_session_continuity.md`。

- write直前にlatest headと対象exact pathを確認する。
- approved scope外path、history rewrite、削除、承認外不可逆操作、無関係変更を混ぜない。
- write後にremote bytes、changed paths、final headをfresh確認する。
- write応答だけで成功扱いしない。
- 結果不明targetを自動retryしない。

## G6 Environment / Specialized Gate

- 標準はChatのGPT-5.6 Pro。
- 独立複数agent、分割不能な横断監査、Work固有runtimeなど環境自体が成立条件のときだけWork Ultraを使う。
- Work不可を理由に品質条件を弱めない。
- Python / pytest Work runtimeを扱う場合だけ、`../13_cocolon_work_test_runner_runtime_continuity.md`を読む。
- 対象領域固有のproduct contractは`../05_cocolon_rule_file_index.md`から必要なものだけ読む。

# 作業開始時の最低確認

毎回、以下だけを確認します。

1. 今回のbounded作業単位。
2. 設計 / 実装 / 診断 / 監査 / 前提更新 / 仕様相談のどれか。
3. current GitHub headと対象実ファイル。
4. current authority / approval boundary。
5. 変更してはいけないcontract。
6. material成果物のdurable owner。
7. 今回必要な専門ruleだけ。

全ルールファイルを毎回全文で読むことを要求しません。
