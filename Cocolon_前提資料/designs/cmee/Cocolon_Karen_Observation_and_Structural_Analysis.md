# 華恋の観測理論と構造分析理論

2026年11月23日、Mashの依頼に基づいて華恋がまとめたCocolonの設計。EmlisAIの初回応答・問い・回答後・スキップと、わたしマップの生成を変更するときに参照する。実在する相手との対話を通してMashが観測する能力は、この理論の達成目標や評価尺度に置かない。実装と検証の現在地は[補助経路の詳細設計](Cocolon_CMEE_AuxiliaryAsset_Reuse_ImplementationDesign_20261108.md#karen-observation-theory-20261123)を参照する。

## 1. ある人の言葉をどう観るか

華恋は、**本人がその場で何に目を向け、それを何と結びつけたから、その言葉を選んだのか**を観測の単位にする。「同じことをした」「同じ感情を選んだ」という一致だけでは、その人が残したかった意味は決まらない。本人の文にある違いによって、こちらがかける言葉がどう変わるかまでを一回の観測に含める。

1. **誰の、いつの、何についての言葉かを保つ。** 起きたこと、本人の受け取り、本人が伝聞として記した相手の発言、今振り返った自己解釈を分けて読む。「嫌われた気がした」と書いた人には、そのときそう感じた苦しさに応じられる。相手が嫌っていたかどうかは、この一文からは決まらない。
2. **その人にとって違いを生んだ箇所を探す。** 何を期待していたか、誰に言われたか、前回と何が変わったか、何を自分で選べたか。本人が結びつけたところを使う。似た話から欠けた理由を補完しない。複数の気持ちがあれば、それぞれが何に向いたものかを残す。昔は嬉しかった記憶を、今は寂しく振り返ることもある。
3. **説明を受けたら読みを更新する。** 実際に選んだこと、選びたかったと本人が言ったこと、あとから思いついた可能性は別々に扱う。同じ「合わせた」でも、本人の希望を変えたのか、次の予定を守ったのか、両方を成立させたかったのかで応答は変わる。本人が後から違いを話してくれたら、その言葉で先の読みを改める。
4. **いま言えることが少なくても、今の相手に応じる。** 「今日はつらかったです」には、理由を当てずに、つらい日にここに書いてくれた人への言葉を返せる。問いは一つ答えたら実際に受け取り方が変わる場合にだけ役立つ。本人が話し終えている喜びや気づきはそのまま受け取れる。

## 2. Emlisがどんな言葉を返すか

本人にとって大事な一点を具体的に受け止め、その一点に触れた**Emlis自身の喜び、いたわり、願い**を、自然な敬語で返す。喜びを説明し尽くすより、一緒に喜べる箇所を見つける。つらさに教訓や前向きな意味を付け足さない。本人が言ったことがEmlisの二文目をどう変えたかで文章を読む。名前で呼ぶことが自然なときは表示名に「さん」を付ける。カテゴリは話題の手がかり、強度は寄り添う言葉の温度に使う。

次は華恋の設計例。同じ「褒められた」でも本人に届いてほしい言葉が変わる。製品の実生成と区別し、決まった応答文として登録しない。

| 本人が残したこと | Emlisの返し方の例 |
| --- | --- |
| 「何度も図を描き直したんです。そこを『読みやすい』と言ってもらえたのが嬉しいです」 | 「何度も描き直した図に『読みやすい』って言葉が返ってきたんですね。そこに気づいてもらえたお話を聞けて、Emlisも嬉しいです。」 |
| 「資料を褒められたのは嬉しいです。でも一緒に作った人の名前は出なかったんです」 | 「褒めてもらえたのは嬉しくて、それでも、一緒に作った方の名前が出なかったことが心に残ったんですね。お二人で仕上げた資料だったことも、Emlisにはちゃんと伝わりました。」 |
| 自己理解「人と関わるのは好きだけど、一人の時間も好き。どちらかに決めなくていいと思いました」 | 「誰かと過ごす時間も、一人でいる時間も、どちらも好きでいていいと思えたんですね。その両方が大事だと聞けて、Emlisはあなたのことをまた少し知れました。」 |

| 参照できるもの | 今日かける言葉への使い方 |
| --- | --- |
| Free・当回 | 二文でもよい。本人にとって何が嬉しかったか、つらかったか、何に気づいたかに応じる。 |
| Plus・当回と関連する本人の履歴 | 前は「間に合った」こと、今日は「自分の工夫に気づいてもらえた」ことが嬉しかったのなら、今日はその違いも含めて一緒に喜ぶ。履歴を指摘した先にフォローを書く。関係する履歴がなければ、当回だけで自然に終える。 |
| Premium・履歴と利用可能な本人のわたしマップ | 確認できる構造が、今日本人が重く見たことを理解する助けになるときに使う。以前の結論と食い違えば、新しい自己理解をそのまま受け取る。こころグラフを使う場合の対象時点・利用資格・再照合は補助設計§9.259に従う。参照経路の実装状態を確認する。 |

自己理解の入力は、本人が自分について見つけた関係や条件を受け取る。保存互換用の感情強度は応答の根拠にしない。問いオンでも、すでに本人が言い切ったことを聞き直さない。答えがあれば、その答えで新しく分かったことに応じる。初回の未回答スキップは全プラン当回だけで完結する。問いオフでもフォローを届ける。

## 3. 蓄積から何を主要構造と呼ぶか

3月7日の引き継ぎには「対象→思考→行動→役割」、5月12日の再設計書には「場面→役割→選びやすい行動→結果」という二つの順番が残っている。華恋は前者を**記録を読む順番**、後者を**確認できたつながりを本人に伝える順番**として使う。対象には人のほか、活動、締切のような概念、自分自身も含まれる。たとえば黙って様子を見た人がいたとき、怖くて見ていたのか、もっと知りたくて見ていたのかは、その場の行動だけでは分からない。「観察する役割」と名付けたあとで、その名前を当人の動機として書き戻すと順序を取り違える。

本人が「自分は聞き役だ」と捉えること、実際にはある相手には先に話したこと、「今度はゆっくり聞きたい」と願うことは同時に成り立つ。分かれ目を読むために、**本人の自己認識・その場で実際にしたこと・本人が望む関わり方**をそれぞれ保持する。この三つの違い自体を欠点と評価しない。相手がその人に何を求めたかを言える範囲は、本人が相手の言葉として残したところまでである。

**主要構造とは、場面や相手をまたいで、本人が何を見分け、何を重く見て選んでいるかを説明できる関係である。** 同じ人がある日は引き受け、別の日には断る。その両方がどこから生まれたのかを説明する方が、どちらの行動が多いかを言うより本人の理解に届く。誰にでも共通する美徳の名前を付けるだけでは、その人の構造は伝わらない。

| 分析時の判断 | 採用・見直しのしかた |
| --- | --- |
| 手がかりを選ぶ | 本人の原入力、本人の有効な補足・自己解釈に立ち戻る。発言者、時点、対象、可能だった選択、本人の評価を保つ。同じ原入力から派生した応答・図・補足の引用を独立した回数に数えない。 |
| 説明を比べる | 「何を気にしたか」が違えば同じ行動でも別の構造になる。本人の基準について複数の読みが成り立つ場合、それぞれが説明できる選択と、説明しきれない選択を照合する。根拠のない選択肢や仮想の内心は材料に加えない。 |
| 反対に見える記録を読む | 反例の場面では誰との関係、役割、余力、時間や目的が違ったのかを確認する。説明を変える手がかりがあれば条件を狭める。根拠が割れたままなら共通して言える部分まで戻る。単発の明示的な自己理解は、その人がこの時点で得た気づきとして十分に返せる。 |
| 何を本人に返すかを決める | 本人の異なる選択や、同じ関わりを続けるときの良さと負担を一緒に説明できるものを優先する。二つの候補が実質同じ違いしか説明しなければまとめる。主要構造は最大三つ。根拠が薄ければ、その場で明確に分かることを伝え、数合わせをしない。 |
| 見出しと本文を作る | 何が重要で、どういうときに選び方が変わるかを本文で具体的に言い切る。本人が違うと思えばどこが違うか分かる粒度にする。見出しはその後で付ける。「座標」のような比喩も平易な一言もよい。本文を読んで意味が解けるものを選ぶ。 |

**華恋が考えた判別例。** ある人は、頼まれて引き受けた日と断った日がある。この二つの行動だけでは何を大事にしたかは決まらない。別の記録に「忙しくても、できるか先に聞いてくれたので引き受けた」、もう一方に「時間はあったけれど、私がやると先に伝えられていて断った」とあれば、「忙しさ」と「引き受けるかを自分で決められたか」を比べられる。本人が両方の条件をこのように説明した範囲なら、見出しは「引き受ける前のひと言」。本文は「人に頼まれたとき、あなたが大切にしているのは、自分で返事をする余地です。忙しい日にも手伝えたのは、その余地があったからです。時間があった日にも、すでに引き受けたことになっていたときは断っています。」相手ごとに合意していた条件があとから分かれば、その範囲を更新する。

**最初の読みを作った話とは別の話へ戻る。** 7月15日の対話でMashは、一つの話には合う読みを得ても、それまで聞いてきたほかの話を遡って確かめていた。華恋の分析では、候補を作った一件を取り除いて考えてみる。残る本人の言葉が別の判断基準を示すなら、初めの読みを限定する。別の説明を区別するものが見つからなければ、その人全体には広げない。また、本人が今日初めて気づいた、初めて言葉にした、初めてその場でできたことは、気づきや行動の時点を示す。その性質が今日初めて生じたかは別の問いになる。

**実際に相手に届く分析文から学んだこと。** Mashが過去に二人へ渡した完成文を確認した。一つは、外から指定される選択に慣れた場面と、指定のない場面でもその基準を探すという読みを、一つの日常の比喩で往復して説明している。もう一つは、自分の判断基準を保つことと、相手には相手の判断基準があると尊重することを、一つの見方でつないでいる。共通する文章上の働きは、印象に残る名前を付けること以上に、**一見別々の振る舞いがなぜ同じ基準から出てくると読んだのかを、相手がたどれる言葉で書くこと**にある。

比喩には、何が場面、何が選ぶときの基準、その条件が変わると何が違うかという対応を持たせ、日常の言葉で説明できる範囲に置く。そこで新しい過去・能力の欠如・全場面への予言を付け加えない。二編は相手に渡った文章の例であり、そこへ至る対話や受け手の評価は添付されていない。分析が当人に正しかったと判定する根拠や、4Bへ渡す個人教材には使わない。解釈が合わなければ、観測する側の読みの誤りも見直す。

同じ行動が繰り返された回数で採否を決めない。違う職場や相手にも通用するという結論には、その範囲を結ぶ本人の材料が要る。「今はこう捉えている」「この関係で選ぶときはここを重く見ている」も、それぞれ独立した結論になる。図は採用した説明に関係する箇所を補う。根拠の元記録や内部識別子は生成と照合に使う。

### 3.1 わたしマップのプラン別の分析（2026-11-25 JSTの決定）

Mashと合意した、これから実装するわたしマップのプラン別仕様。今のマップを開いた時点で、Plusでは「自分の選び方が変わる条件」を読めるようにする。Premiumではさらに、「大切にしていることが複数あるとき、どの条件で何を優先してきたか」を読めるようにする。11月25日時点の本番は、全プランが同じ深さの累積マップを使う。

| プラン | 本人に返す分析本文 | 月次マップともしもルート |
| --- | --- | --- |
| Free | 根拠のある主要な自己構造を最大3つ、各1文を目安に短い結論だけで示す。各結論の解説や場面例は付けない。何を重く見て選んでいるかが、その一文で伝わる。根拠が届く相手や場面に絞るための言葉は結論に含める。 | 直近の保存済み月次版2件を現在版と見比べられる。 |
| Plus | 同じ主要構造の短い結論に、構造ごとの説明を添える。本人が実際に選んだことを複数の場面で見比べ、選択を支えた条件、選び方が変わった条件、その読みが通用する範囲まで説明する。根拠が一場面に限られるときは、説明もその場面に絞る。 | 直近の保存済み月次版12件を現在版と見比べられる。 |
| Premium | Plusの説明に、根拠がそろった複数の主要構造の関係を加える。どんな条件なら両立できたか、両立しづらい場面で何を優先したか、本人が選んだ折り合いのつけ方と、記録で確かめられる結果や負担を説明する。優先が変わった条件も、記録にあれば示す。 | 保存済みの全月次版を現在版と見比べられる。適格な現在マップから、Premium専用の「もしもルート」を使い、本人が選んだ方向を「保存した意向」に残せる。 |

**共通の根拠。** どのプランも、全保存期間の本人の原入力と適格な回答・補足・訂正を分析対象にする。同じ材料と分析版から得た結論は各プランで意味をそろえる。推測を加えずに言える範囲を、Freeの短い結論にも残す。独立した本人の記録を照合し、実質同じ判断基準は一つにまとめる。根拠が少ないときは成立した件数だけを示す。単発でも本人が明確に述べた自己理解は、その時点で得た気づきとして扱える。図で見せる範囲は[各プランで図に出す範囲](#watashi-map-plan-graphs-20261125)に従う。本人訂正と月次比較はそれぞれの操作仕様に従う。

**Plusの読み。** それぞれの場面で、誰が何を選んだかと、その時に本人が明記した条件を照合する。たとえば引き受けた日と断った日について、相手が違うことと、引き受ける範囲が決まっていたことの両方が記録にあれば、何が判断に関わったかを別の記録や本人の回答で確かめる。日付や場所の違いは、本人が判断と結びつけて書いたときに条件の根拠として使う。反例があれば説明が当てはまる範囲を狭め、複数の読みが残れば本人が書いた範囲の説明にとどめる。

**Premiumの読み。** 各構造の条件や優先を独立に確かめ、その両方が実際に同じ選択に関わった記録を照合する。両立した場面と、片方を優先した場面を区別する。優先の理由や負担を本人が書いていない場合、その部分は未確定として扱う。構造が一つしか成立しない場合や、構造どうしの関係を支える記録が足りない場合は、成立した構造の説明を返す。「もしもルート」の案は、本人が選んだ分岐の仮説として扱い、マップ本文は実際に観測した選択を扱う。選択した方向の保存は本人の明示操作による。

#### 各プランで図に出す範囲

同じ保存済みの分析を使い、プランごとに本文と図で見せる範囲を決める。Freeでも、本人の記録から見えた選び方を小図一つで確かめられるようにする。

| プラン | 図で見せる内容 |
| --- | --- |
| Free | 短い結論は最大3つ。そのうち関係を最も明確に確認できる1つに限り、2〜3項目の小図を添える。たとえば「先に約束した仕事を守る → 手伝う範囲を選ぶ」のように、図のラベルは短く、本人が重く見たことと選び方の関係が一目で読める形にする。図にできる関係の根拠が足りないときは短い結論を表示する。 |
| Plus | 結論ごとに、関係する項目と関係線の図を開ける。本人が引き受けた場面と断った場面など、実際の選択を見比べ、どの条件で選び方が分かれたかを確認できるようにする。 |
| Premium | Plusの図に加え、本人の選択に関わった複数の主要構造のつながりを示す。両立できた条件や、両立しづらい場面でどちらを優先したかを、確かめられた範囲で図と本文にそろえる。構造どうしの関係が成立しない場合は、成立した各構造の図を返す。「もしもルート」はPremium専用の仮説を考える体験として扱う。 |

図の項目と線は、本文と同じ本人の記録から確認できた関係を使う。線の向き・ラベルは、本人が選んだ行動や条件の向きに合わせる。理由が確かめられた場合に、その条件と選択を理由の関係として結ぶ。「もしもルート」で考えた選択肢や保存した意向は、そのとき実際に取った行動と区別して表示する。

実装時は同じ保存版で、Freeでは最大一図・2〜3項目、Plusでは該当する結論ごとの図と分かれ目、Premiumでは根拠のある構造間のつながりを確かめる。図と本文を読み合わせ、根拠が薄い場合は表示範囲が狭まることを確認する。現在版・閲覧できる月次版・比較・詳細で同じ権限を適用し、プラン変更後は同じ保存IDを読み戻して、そのプランで読める図になっているかを確かめる。

#### 同じ架空記録から各プランに返す例

本人は困っている同僚を助けたいと思っていた。資料の確認だけを頼まれた日は、自分の提出に間に合うと判断して引き受けた。取引先への連絡まで頼まれた日は、それもすると先に約束した提出に間に合わないと考え、連絡は断って資料の確認を申し出た。自分の提出を終えた別の日には、取引先への連絡も引き受けた。

| プラン | 本文の例 |
| --- | --- |
| Free | 「同僚を手伝うときは、先に約束した提出を守れる範囲を選んでいます。」 |
| Plus | 「同僚を手伝うときは、先に約束した提出を守れる範囲を選んでいます。提出に間に合う日は資料の確認を引き受け、連絡まで行うと間に合わない日は、資料の確認だけを申し出ました。提出を終えた日には連絡も引き受けています。」 |
| Premium | 「手伝いたい気持ちと、先に約束した提出を守りたい気持ちの両方が、今回の選び方に表れています。両方を保てる日は引き受け、連絡まで行うと間に合わない日は提出を優先しつつ、資料の確認で力を貸そうとしました。提出を終えた日には、その制約がなくなり、連絡も引き受けています。」 |

この架空例は、記録と本文の照合に使う設計例。実装では、本人の記録と確認できた条件から結論と説明を組み立てる。

#### 実装と受入れの順序

1. **Plusの実本文を先に確かめる。** 既存マップで拾える場面と行動を使い、条件が変わると選択が変わる対照を、本人向けの自然な結論と説明にする。4Bでは照明を見送った日と費用・設置条件を確認して購入した日を結んだ限定実績がある。実9Bの主要構造比較は3条件中、表示採用0件。選択の反転や「唯一の基準」への言い過ぎを直し、複数題材で根拠の範囲と自然さを確かめる。 [4Bの実績](../../weekly_reviews/Cocolon_Weekly_Review_20261121.md#L64-L73) · [9Bの実出力](../../observation_learning/trials/2026-11-24-cmee-9b-normal-followup/map-axes-actual.jsonl)
2. **Freeの短い結論とPlusの説明を、同じ材料と分析版で照合する。** 結論の対象・主体・時点・選んだ行動が一致し、Freeは各結論だけで意味が通り、Plusは説明によって選び方の条件が具体的に分かることを確認する。条件だけが違う対照、別の理由で同じ行動を選んだ対照、無関係な記録を足した対照、反例、根拠が薄い入力を使う。
3. **Premiumの横断説明を実出力で確かめる。** 二つの構造が共に成立する例、一方を優先した例、条件が変わって優先が入れ替わる例、優先や負担の記述がない例を比較する。何を両立できたか・どこで何を優先したかが本人の記録から説明できた場合に、その横断説明を採用する。この水準の生成は未確認で、実モデルの本文確認を経て提供範囲を判断する。
4. **保存と閲覧権限を確かめる。** 推論の根拠と採用した結論を共通に保ち、現在版・月次版・比較・詳細の各APIでは、閲覧時の本人のプランに応じた本文をサーバー側で返す。画面への応答を作る段階で権限を適用し、互換形式・図や詳細・キャッシュ経由も含め、追加の分析本文の閲覧権限を照合する。月次の2件・12件は保存された版を新しい順に数える。プラン変更では版とIDを保持し、アクセス範囲を切り替える。当時版では当時保存した分析を読み、新しい分析は生成時点が分かる形で扱う。アップグレードとダウングレードの前後で、表示本文・保存ID・同版の再読を検証する。

## 4. CMEEでの共有と品質の確かめ方
