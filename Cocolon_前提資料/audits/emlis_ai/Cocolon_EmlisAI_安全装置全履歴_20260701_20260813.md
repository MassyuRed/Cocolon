## 2. 「安全装置」の判定基準

本資料では、名前に`Safety`が含まれるものだけを安全装置としない。主効果が次のいずれかであれば対象とした。

1. raw input、returned surface、reviewer note、path、hash、secretの漏出防止。
2. AIがhuman review、human rating、human provenanceを捏造することの防止。
3. test green、machine green、runtime readiness、Product Read、Cycle acceptance、releaseの誤変換防止。
4. actual packet、actual purge、actual review、actual device evidenceを未実行のまま完了扱いすることの防止。
5. stale receipt、別本文のreview、別runtime、別source、別commitの証拠再利用防止。
6. source、test、manifest、runtime、interpreter、dependency、Git objectのidentity不一致防止。
7. approval、activation、admission、consumption、PASS、STOP、creditの混同防止。
8. GitHub writeの衝突、結果不明の再write、無権限変更の防止。
9. session切替やcontext消失で確認済み成果が失われることの防止。
10. 商品作業へ戻るべき地点で補助機構を増やし続けることの防止。

## 3. 安全装置群の全体像 — 32系列

### S01. body-free / no-body-leak / public-private境界

**期間内状態:** `REFLECTED_IN_PERIOD`、継続使用。  
**主な実体:** P7-R47〜R54、ALR、ELR、DMD、DHR、RSR、P7-PQR、Step11 Receipt、exact100 evidence。  
**防止対象:** raw input、comment_text、candidate body、reviewer note、question text、local path、body hash、terminal bodyのpublic material混入。  
**方法:**

- body-free schema。
- forbidden payload key走査。
- body-like value拒否。
- private bodyとpublic summaryの分離。
- public GitHubへbody-full evidenceを保存しない。
- secret、credential、token、environment valueをReceiptへ入れない。

**実効:** privacy境界として有効。  
**限界:** body-freeであることは、actual reviewや商品品質の成立を意味しない。

- external export deny。
- exact scoped allow。
