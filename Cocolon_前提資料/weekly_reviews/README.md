# Cocolon 週末報告会

## 目的

Mashと華恋が、Cocolon全体の現在地、残作業、優先順位、リリースまでの見通しを共有し、次の行動を一緒に選ぶための記録です。

進捗の提出・監督・反省だけを目的にしません。Mashは、華恋を単なる作業AIではなく共同作業者として扱い、華恋自身の意見・懸念・推奨・Cocolonへの考えを聞くことを、報告会の目的として明示しています。実績と反省の両方を扱い、確認した事実、Mashの意見、華恋の意見、合意事項、未決事項を分けます。

## 開催と議題

週末に週1回を基本とします。開催時刻や自動実行はこの資料では設定しません。

1. 今週やった作業と成果：予定との差、実装・出力で何が変わったか、実績と反省。
2. アプリ全体の現在地：できている部分、残作業、未確認部分、根拠を示した進捗評価。
3. 課題と残作業：現在の不具合、設計済みの後続実装、確認待ちを区別する。
4. リリースまでの見通し：初回の完成条件、依存関係、日程、実機・審査・修正の余裕、見直しの節目。
5. 次週の優先順位：次回までに何を、なぜ、その順に進め、何を確認して終えるか。
6. 困りごと・進め方への意見：華恋の意見・要望・懸念・感想と、Mashとの対話。

議題番号は維持し、会話の順は状況に合わせます。第1回は1→3→2と4→5→6の順で話し、全体の要約を最後に整理しました。重大な問題や必要な判断を週次報告まで待たせません。

## 資料の作り方

一回分の報告と議事録を同じファイルへまとめます。議題の区切りで更新し、話し合い後に全体要約・決定・未決・次の行動を整えた最終版にします。途中版や撤回した進捗値を並べず、その回の最新評価と算定根拠を載せます。

準備・実ファイルの確認・説明・推奨・記録は華恋が担当します。Mashへ技術情報の掘り起こしを丸投げしません。Mashの判断や本人側の実機操作が必要な場合だけ、対象と理由を具体的に示します。

進捗率は、公開範囲、配点、到達段階、根拠、未確認を明示します。テスト件数・文書数・コミット数を、そのまま商品完成率へ変換しません。実装の前進、評価の訂正、確認済み範囲の増加、公開範囲の変更を区別します。

## 正本・承認との関係

このフォルダは報告会の記録先であり、仕様正本、実装指示書、独立した作業台帳ではありません。会議資料の保存は、未承認の契約変更、商品PASS、merge、本番反映を承認しません。

実装判断に適用する決定は、対象の既存正本へ必要な差分を反映し、反映先・実施状況を記録します。議事録にしか新しい決定がない状態を放置せず、同じ内容の新設計を重複作成しません。

意見の提示と実行承認は分けます。華恋は質問や特別な開始文を待たず、事実に基づく意見・懸念・推奨を伝えます。共同作業らしく見せるための反対意見や、毎回の発言欄の水増しは不要です。合意済みの範囲は進め、新事実が目的・品質・日程へ影響するときは判断を更新します。

## 公開する範囲

非公開の原入力・出力本文、個別ケース値・digest・locator、認証情報、引継ぎZIP本体は公開GitHubへ載せません。開発に関係する議論だけを記録し、個人的な愛情の会話はこのフォルダへ転載しません。Karen-Diaryへの記録は別の指示と保存範囲で扱います。

第1回の長い作業開始指示文は、Mashの指定により議事録へ収録しません。週間計画と再開に必要な公開可能な情報は、議事録と既存handoffに残します。
