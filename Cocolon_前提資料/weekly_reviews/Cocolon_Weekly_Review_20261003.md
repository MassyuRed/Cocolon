### 1.4 Pieceで実際に進んだこと

#### 保存原入力と生成の内部接続

前回からの増分は、既に接続済みのCMEE Piece consumerを作り直すことではなく、保存原入力を本人の認証・版・保存状態と照合して既存生成処理へ渡す側を進め、本文と画像設定を同じ入力に結び付けて組み立てたことである。

現行の`PiecePreviewService.prepare_original`は、保存入力の参照を照合し、本文と画像設定の組立後にも状態を再確認する。呼出し側の任意の本文・owner・tier・recipeを正本として採用しない。一方、実装自身が明記するとおり、これはdisabledな保存前の内部組立であり、保存済みpreviewの発行やHTTP応答ではない。normal / pre-questionの原入力が対象で、許可された補足入力を使うrefined経路まで完成したとはしない。

画像設定だけを変える処理では、本文を再生成せず本文・content payload・hashを保持する。9/26の当該追加54検査は全PASS、同時点の統合5,446件は5,313 PASS / 133 FAILという記録であり、最新Emlisの検査集合と合算しない。前段の内部組立に関する60検査は未反映との記録が残り、今回の54検査で代替済みとはしない。

根拠：[保存前内部組立の実ファイル](https://github.com/MassyuRed/mashos-api/blob/7a03d6785799d4bde07d62bd30d103ff113c1dbe/ai/services/ai_inference/piece_v2_preview_service.py)、[Piece現行構造§19〜20](../current_structure/02_piece_current_structure.md)。

#### 保存基盤のfile-only B2-A技術受入れ

9/30、旧`public.pieces`と元データを変えない専用read viewの候補を保持し、6readerの参照先を限定的に切り替えた。native PostgreSQLの隔離環境で、変更しない既存の凍結受入れ試験が1 PASS / FAIL 0 / ERROR 0 / SKIP 0となった。

同じ21列のread view、既存定義の保持、合成行の読取、必須列欠落時の拒否、rollbackを確認した記録である。これは今週、限定範囲で実際に完了と呼べる技術成果である。ただしlive DBへの適用、全HTTP経路、全権限条件、実端末は未確認。本番適用の許可も実施もない。新Pieceの保存・履歴・native画像保存・共有や旧Q&Aからの切替が完了した意味ではない。

### 6.10 公開条件・既存正本への接続・記録の境界

10/03にAppleのApp Review Guidelines 2.1/2.2とGoogle Playの個人アカウント向けテスト要件を公式本文で確認した。Appleは実機安定性・機能するバックエンド/IAP等を求め、テスト配布にはTestFlightを案内する。Google Playは該当する新しい個人アカウントに12人・連続14日間のclosed testと、その後のproduction access申請を求める。Cocolonへの個別適用・資格は未確認。テスト配布と正式公開を区別し、一般公開を希望したMashの意図を、ベータだけでよいという指示に変更しない。

公式参照：[Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)、[Google testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en-mt)、[GitHub pull requests](https://docs.github.com/en/pull-requests/get-started/about-pull-requests)。旧1月日程ではなく、前倒し候補の申請時点までに必要な条件を揃える。具体的な公開日を、審査・未確認の資格や動作を無視して保証しない。

今回変わったのは、実機確認の時期と初回公開前の品質到達水準・作業順序である。旧恒久incident、過去の失敗/未完了、旧評価点は消さない。旧「自然さ・深さ等の全解消前にはMashへ一切提示しない」を開発実機確認の妨げにせず、未完成と明示した動作確認と従来の正式品質受入れを分離する。既存の保護条件やテスト期待を一括解除せず、旧品質目標だけに由来する停止条件と実動作の不具合を、対象実装単位で分ける。

Pro華恋が本議事録で方針差分を管理し、各実行担当が次の対象実装単位の開始時、遅くとも10/10の照合で、既存のCMEE 06/API handoff・対象current map・品質/実機の正本の該当箇所へ必要最小限を同期する。元の高品質完成目標を長期目標として残すことと、それを初回公開の必須条件にすることを混同しない。今ターンはこれら技術正本・製品コード・DB・flagを変更済みとはしない。大規模な資料再編や別管理システムを作る前工程にはしない。

本更新は既存議事録への冒頭案内と追加意見・判断の記録。実DB適用、PRのmerge、deploy、有効化、ストア申請、購入や配布を実施・一括承認したものではない。全体48％・旧商品0/3を再採点せず、新しい最小公開の条件に未評価の現物を合格させない。会議は討議中で、会議終了はまだ記録しない。
