## 1. 現在地と教材の用途

実際の入力項目に合わせた短い架空記録を起点にする。現在はD05まで採録。二つの問い・本人役の回答とMashの観測文、復唱と需要についての問題提起を保存した。§3は問いより前の設定を保持し、実演の記録は§6へ追記する。

今回の認識は[前回ノート§8](../OBS-20261022-002/02_learning_notes.md#daily-input-agreement)を参照する。長文相談を書けることを前提にせず、普段の言葉に本人の見方が表れる場合を扱う。全入力への深読み・質問・新発見を必須にしない。

この題材は実ユーザーの代表標本ではない。初期入力だけから分かること、本人の回答で初めて分かること、観測者の仮説を分けるための教材候補として保存する。唯一の原因・正解人物像を当てる試験にはしない。

## 2. 最初に見える本人source

D00の感情選択・思考・行動・カテゴリーのみ。年齢、職業、性格、過去履歴、相談の意図、相手の本心は初期入力にない。最初から解釈例・質問例・期待する結論をMashへ見せない。

不安（弱）という選択を、病名や深刻度の診断、相手が怒っている証拠にしない。「大丈夫」の本人にとっての意味、「気になる」の対象・理由は、初期入力だけでは確定しない。

## 3. 最初の問いより前に用意した本人役の回答用設定

以下は華恋が架空入力者として回答を一貫させるための事前設定。D00には含めず、聞かれた範囲へ回答したものだけが観測者の利用できる本人の説明になる。

| ID | 出来事・本人の認識として固定する内容 |
| --- | --- |
| F01 | 友人から小説を一冊借りた。借りたときは「読み終わったらでいいよ」と言われ、固定の返却期限はなかった |
| F02 | 後から本人が「週末に返すね」と伝え、友人からは「了解」と返っていた。友人に返却日を指定されたわけではない |
| F03 | その週末までに読み終わらず、実際の返却は数日後になった。遅くなると分かった時点で連絡せず、返すときまでそのままにした |
| F04 | 今日、本を返して「返すの遅くなってごめん」と謝った。友人は「大丈夫だよ」と答えた。本人には強く責めるような言い方には聞こえなかった。友人が内心どう思ったかは分からない |
| F05 | 本人は「遅くなるって一言連絡できたのにな」と思い出している。返した事実や友人の返事は認識しているが、それでその思いが全部消えたわけではない |
| F06 | 本人は、返す日が変わるなら相手もそれを知っている状態にしておきたかった、と説明できる。相手が実際に待っていた・困っていた、という事実は設定していない |
| F07 | 「気になる」は友人が怒っているかだけを指すものではない。連絡をしなかった自分の対応も気になっている。人格・性格の評価へ広げない |
| F08 | 読み終わるのに予想より時間がかかった。細かな日程、遅れた日の全行動、仕事・家庭・健康上の事情は未設定であり、本人の動機として補わない |
| F09 | 同じ友人との過去の出来事、他の相手との類似経験、幼少期、診断、固定的な価値観の優先順位、今後の行動予定は未設定 |
| F10 | 入力はその時点の気持ちを残したもの。助言・分析・長い相談の依頼を出した、という設定にはしない |

F05〜F07は本人が説明できる一要素であり、「連絡しなかったこと」を唯一の原因や、当てるべき正解にしない。相手の本心、固定的な性格、全ての気がかりの解決は設定していない。

未設定を、本人の「覚えていない」「自分でも分からない」という心理状態に置き換えない。固定された本人の説明と、未設定の事項、問いを受けてその場で考えた仮定を区別する。Mashの仮説に合わせるための過去や理由の作り足しは行わない。

## 4. 実演後に採録すること

実際に発言されたものだけを追記する。

- 初期入力で何を事実として受け取り、何を保留したか。
- 問いがあれば、Mashの問いと華恋の本人役の回答。
- 回答によって、どの読みを維持・修正・撤回したか。
- 着目理由や技術についてMashが説明した内容。説明されていない内的思考は復元しない。
- 問いを出さず終えた場合は、その実際の観測・受け取り。後から質問や結論を補わない。

## 5. 学習への利用と今回の効果

最初の入力だけの応答と、本人回答を得た後の応答を混ぜない。教材化時に利用できる根拠は、その段階で提示済みの入力・実回答に限定する。未提示設定を知っていたように本文・問いを編集しない。

学習用の完成形式への変換、学習／評価への割当、モデル推論、GPU起動、追加学習、CMEE接続、製品コード・API・DB・配置は未実施。D00準備時点では実演前だった。その後のD01〜D05は§6へ採録したが、最終的な教材解釈・用途・商品判断は未確定のため、完成したお手本ファイルはまだ作っていない。

今回の反映は合意の記録と材料準備。STRUCTURE_MAP_DELTA_NONE、ADMINISTRATIVE_ONLY。D00提示後の現在地は§6を参照する。

### 初期入力と回答後の根拠を混ぜない

週末という本人が伝えた返却時期、連絡しなかったこと、友人への影響の懸念は、最初のD00にはなかった。D05はD02・D04の回答を受けた後の観測文であり、D00だけからこれを生成できた教材に編集しない。

D04の「待たせたり困らせたりしていたかもしれない」という不安の具体的な文言は、対話中に華恋が架空入力者役として回答したもの。事前設定F06の「相手が実際に待っていた・困っていた事実は設定していない」を維持し、この回答の文言そのものが質問前から明記されていたかのように§3を書き換えない。本人役の懸念と友人の実際の状態を分ける。

### 華恋による教材上の留意点（Mash未確認）

今回、観測者側が質問によって新しく知った内容と、本人が質問を通じて新しく理解できた内容を同一視しない。架空入力者役の華恋が設定と整合する説明を返した実演であり、実ユーザーの気づき・安心・満足が実際に生じた証拠ではない。復唱に見える最終文だけから需要の肯定・否定も確定しない。

MashのD05は、事実の整理と商品として受け取る価値の関係を検討する問題提起として残す。「全て復唱でよい」「以前のEmlisの復唱も商品合格だった」という教示へ広げない。
