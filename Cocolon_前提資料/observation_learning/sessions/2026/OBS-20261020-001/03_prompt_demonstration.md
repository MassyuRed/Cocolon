# OBS-20261020-001：27Bへ渡す観測のお手本

用途：指示文に実演を添える試験の教材。モデルへの追加学習データではありません。

## 2. モデルへ渡す本文

次の一つのtextブロックが、指示文とともに渡す教材本文です。本文外の出典表や運用メモはモデル入力へ混ぜません。

```text
【観測のお手本】
観測者はMash。相談者の入力・回答は華恋作成の架空例。原文の一部を抜粋・要約した。この人の動機を別の人へ当てはめず、問い方と暫定性を参照する。回答形式は別途の指示に従う。

相談の要約（華恋）：写真サークルの展示会で、頼まれてまとめ役を承諾した。自分で決めてほしいが、相談なく進むと引っかかる。作品時間が取れず、「みんなで作っている」感覚も薄い。

Mashの問い：なぜ、まとめ役を引き受けましたか？
回答の抜粋：去年やったので、私がやるのが一番早いかなと思いました。それに、去年は大変だったけれど、終わったときは嬉しかったんです。

Mashの問い：なぜ、相談もなく仕事が進むと不満に思いましたか？
回答の抜粋：案内画像は、私も少し考えていたんです。
完成したものが送られてきて「あ、もうこれになったんだ」と感じました。
私が考えていることも、先に伝えてはいなかったんですよね。

Mashの問い：あなたの理想の展示会とはなんですか？
回答の抜粋：自分の写真を、納得できる形で見てもらいたいです。それと、ほかのメンバーが何を撮って、何を見せたいのかも知りたいです。
同じ組の別回答の抜粋：案を持ち寄って話した結果なら、自分の案がそのまま通らなくても受け入れられる気はします。

Mashの問いの末尾：他の人にやってほしいなら引き受けたつもりだったあなたの役割とはなんでしょうか？
回答の抜粋：「まとめ役」は、会場との窓口になったり、必要な作業や締切を確認したりする役割だと思っていました。実際の作業は、みんなにも担当してもらうつもりでした。
同じ組の別回答の抜粋：一番は、自分の作品に使う時間が取れないことです。

Mashの暫定観測の要約（華恋）：展示会を「感性の交流の場」として求め、自分の予測範囲で進んでほしい願望が負担につながっているように見える。
Mash自身の説明：この読みは情報がまだ足りてないのをわかってて憶測で言ってる。
華恋の未確認点：知らずに進むこと自体への抵抗か、予算・締切・後の対応への心配かは分けきれていない。この仮説を正解として扱わない。

問いの狙いとしてMashが説明したこと：その人の判断基準や感情の理由を勝手に決めないために、相手から引き出してその内容を使う。
各問いの細かな設計理由すべてが説明されたわけではない。

反対の回答の条件例（Mash）：他の人が決めてくれたことでホッとした／自分の担当以外はみんなが進めてほしい、などがあれば「もっと探ったかもね」。
これは仮定であり、この相談者の実際の追加回答でも、Mashが完了した仮説修正でもない。

Mashの教示の要約（華恋）：相手の価値基準を学び、思考経路を辿る。経験は探る場所を見つけ、自分の価値観の持ち込みにも気づくために使う。行動から人物を二種類へ分類する技術ではない。
【お手本ここまで】
```

## 4. この教材で確かめられることと、未完の部分

本人の言葉を理由・目的・役割の理解へつなげる問い方と、仮説を暫定のまま確かめる姿勢を示します。Mashの口調や展示会についての結論を模倣させる教材ではありません。

この観測会では、反対の追加回答を受けてMashが実際に読みを修正するところまでは実演していません。したがって「質問→回答→修正」の完成済み正解例があるとは扱いません。未実施の追加回答や更新後の観測文は作り足していません。

華恋の編集上の重点は次の三つです。

- 行動から理由を補う前に、本人が使っている基準を尋ねる。
- 相手の回答のどこが、最初の読みを支えるのか／揺らすのかを見る。
- 理由が未確認なら、助言や性格判定へ進めず、理解に必要な問いを選ぶ。

## 5. 次の試験での使い方

教材準備とモデル実行を分けます。今回は教材本文と出典の整理までで、GPU起動・推論・追加学習は行っていません。

次は同じ27B・同じ生成設定で、新しい相談を「従来の指示のみ」「同じ指示＋§2のお手本」で比べる案です。初回の応答と問い、その問いに対応する追加回答を受けた更新を読みます。問いは既存の指示どおり一つとし、教材に歴史的な複数の問いがあることを一度に質問を並べる理由にしません。

見る内容は、本人の判断基準を尋ねる問いになっているか、入力にない動機を足さないか、合わない回答で理解を更新するか、お手本の文型や結論を他人へ当てはめていないかです。お手本付きで改善しても、モデルの恒久的な学習や追加学習後の成功を確認したことにはしません。

- この展示会とその派生例は、教材に触れた事例として扱います。独立した未知事例へ数えません。
- 先行の連絡係テストも題材が近いため、同系統の結果だけで広い適性を主張しません。
- §2の文字数はトークン数ではありません。実行時には実際の27Bのtokenizerで、既存SYSTEM・教材・相談・追加回答・直前のモデル応答・生成枠を含めてコンテキストへ収まるか確認します。収めるために本人の回答を黙って切りません。
- 教材本文に、今回の27B／120Bの試験回答・評価用の新しい相談・非公開の実在者記録は混ぜていません。
