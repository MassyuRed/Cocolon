## 今回、Mashから教わった中心原則

- 行動や発言だけから、その人の判断基準や感情の理由を決めない。「なぜそうしたのか」を問い、相手の認識を引き出して材料にする。
- 相手自身の価値基準を学び、その基準から思考経路を辿る。観測者の価値観を、相手を説明する基準として持ち込まない。
- 経験は、どこを探れば理解が進むかに気づき、自分の価値観を使ってしまっていることにも気づくために使う。行動から人物タイプを決める統計的分類を学ぶことを、Mashの経験の目的へ置き換えない。
- 仮説は暫定のものとして扱い、本人の回答や言動との整合を確認する。合わない回答が出たら、条件や意味をさらに探り、理解を更新する。
- 観測の応答、問い、回答を得た後の理解更新を一緒に残す。

以上は第1回のMashの説明を華恋が整理したものです。[原文D11・D13](sessions/2026/OBS-20261020-001/01_dialogue.md#d11)も参照し、整理への訂正があれば原文を保持して更新します。今回作った記録と、実際のモデル学習の実行は区別します。

## 保存単位

1回の観測会につき `sessions/YYYY/OBS-YYYYMMDD-NNN/` を作り、原則として次の2ファイルにまとめます。NNNは同日内の連番です。

| ファイル | 残す内容 |
| --- | --- |
| `01_dialogue.md` | 元の相談入力、Mashの問い、相談者の回答、Mashの観測、華恋との教示対話。発言ID・話者・役割を付ける |
| `02_learning_notes.md` | 本人の発言、Mashが説明した技術、華恋の解釈、仮説の根拠・未確認・修正点を原文IDに結び付けて整理する |

始めるときは[SESSION_TEMPLATE.md](SESSION_TEMPLATE.md)を使います。1回ごとのフォルダに閉じることで、後から件数が増えても材料と整理の対応を保ちます。

## 記録の扱い

- 架空の相談者、実際の相談者、作成者、実演者を明示します。華恋が相談者として作った回答と、講評する華恋の発言も区別します。
- 原文の「かもしれない」「ように見える」、言い直し、留保を保持します。華恋の要約で断定へ変えません。
- 途中送信や重複を除いた場合は、その範囲を明示します。全文エクスポートではない採録を、完全なチャットログと呼びません。
- 原文は後の解釈に合わせて書き換えません。訂正は、誰が・何を訂正したかを追記します。採録の誤記を直す場合も訂正履歴を残します。
- 華恋が補った狙いや解釈は「華恋の整理／Mash未確認」とします。説明されていないMashの思考過程を復元したことにしません。
- 教材候補の保存、教材としての整理、学習用データへの変換、モデルへの学習、未学習の入力での評価を別の段階として記録します。
- この記録をそのまま自動学習へ投入しません。将来の学習／評価への割当と変換方式は未決です。同じ事例の派生版を独立した未知事例として数えません。
