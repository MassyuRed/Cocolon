# 観測会の記録ひな形

`sessions/YYYY/OBS-YYYYMMDD-NNN/` に、以下の2ファイルを作ります。書かれていないことを推測で埋めず、未説明・未確認と記します。空欄を埋めるためにMashへ毎回同じ質問をする必要はありません。

## 01_dialogue.md に書くこと

### 基本情報

- セッションID／日付・タイムゾーン
- 題材／元の資料・対話の出所
- 相談者が架空か実在か／入力と回答の作成者
- 観測・教示の担当者
- 採録範囲／省略・重複・途中送信の扱い／原文が取得できていない範囲

### 発言の保存

`D00` から順に、発言ごとに次を付けます。

- 発言ID
- 話者：Mash／華恋など
- 役割：相談入力／相談者としての回答／問い／暫定観測／教示・訂正／講評
- 本文：原文を保持。本文内の留保・言い直しも残す

相談者への問いと、観測者に方法を聞く問いを混同しません。未回答の問いは未回答として残します。後からの補足は新しい発言IDで追記します。

## 02_learning_notes.md に書くこと

### 現在地

- 素材保存／整理中などの状態
- 華恋の整理について、Mashが明示確認した範囲／未確認の範囲
- 学習用データへの変換・実際の学習・評価の実施有無

### 観測と教示

必要な項目だけ、原文IDへのリンクを付けて整理します。

| 区分 | 残すもの |
| --- | --- |
| 本人の説明 | 相手が語った出来事、価値基準、判断・感情の理由。観測者の解釈と分ける |
| Mashの着目・仮説 | 手がかり、いつ浮かんだか、暫定性。本人が説明した範囲を示す |
| 問いと回答 | 実際の問い、回答によってわかったこと。問いの狙いはMashの説明の有無を示す |
| 理解の更新 | 支持・疑問・訂正・撤回のきっかけ。例示された反対証拠と実際の回答を分ける |
| 価値観の持ち込みへの気づき | どこに観測者の基準が入ったか。説明がなければ未説明とする |
| 華恋の整理 | 教材としての整理と、Mash未確認の解釈 |
| 未解決 | まだ確かめていないこと、言い切れないこと、実演を終えた事情 |

### 訂正履歴

日付／対象／誰による説明・訂正か／更新した理解／原文の参照先を記します。人物タイプや完成した正解図を必須欄にしません。

### 今後の利用

学習／評価への用途が未決なら未割当と記します。元の対話と教示の保存を、モデルが能力を獲得した証拠へ変換しません。
