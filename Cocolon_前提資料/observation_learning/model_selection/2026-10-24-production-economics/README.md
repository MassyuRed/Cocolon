# 680円／1,480円 — 提供方式と利用量を固定した月額原価試算

2026-10-24 JST／華恋。**計算基準を固定して算出した結果、有料50人・無料950人の基準負荷を、25出力token/秒等の参照性能で提供する案は不成立。680円／1,480円を、この案で採算確認済みの売価として確定して育成へ進むことは推奨しない。**

これは本番の請求実績ではなく、明記した使用量・性能・起動条件による予算試算である。価格そのものが一般に成立しないという結論にはしない。どの数字を変えれば結論が変わるかも同じ計算へ残した。

## 1. 今回固定した提供案

| 項目 | 計算基準 |
|---|---|
| モデル | Qwen3.5-4B＋独自LoRAを三中核で共用する候補。採用・学習・配備は未実施 |
| 提供 | Runpod Serverless Flex 24GB群、worker最小0／最大4、基準はworker同時処理1 |
| 停止 | idle timeout 5秒。リクエストのない間はscale to zero |
| モデル保存 | network volume50GB。既存共通予算へ560円を含め、再加算しない |
| context | 73,728を候補とし64,000入力＋4,000出力を切り捨てない。長文搭載・速度は未検証 |
| 公開単価 | 24GB Flex $0.69/時間。160円/$の仮定で110.4円/課金時間 |

vLLMにはQwen3.5およびLoRA提供の経路があるが、受領adapterとの実互換・長文メモリ・本番性能は未確認。この案は計算用に固定した候補であり、環境を作成・有効化していない。

GPU課金はモデル読込・実行・停止前待機を含むworker稼働時間。container pull／cached weight downloadは通常停止中の非課金で、モデルをGPUへ載せる時間と混ぜない。container保存等は共通予備2,440円で賄えると仮置きし、超過分は別途増額となる。すべての規模で予備が十分とは保証しない。

## 3. GPU時間に置いた参照仮定

| 項目 | 基準 | 根拠と限界 |
|---|---:|---|
| 出力処理 | 25token/秒/GPU | [短文A40の受領結果](../../trials/2026-10-24-qwen4b-9b-comparison/README.md)の概数。24GB GPU・vLLM・長文・LoRAへの移植は仮定 |
| 入力処理 | 1,000token/秒/GPU | 未測定の計画値。長いprefillをゼロにしないため別計上 |
| 起動回数 | 生成数の10% | 平均10要求/稼働episodeという感度仮定。実arrivalから導出した予測ではない |
| 一起動のGPU load | 30秒 | 未測定の計画値。前のPod load秒をServerless cold start実測と扱わない |
| 終端待機 | 一episode5秒 | 同じworkerを再利用した各要求へidleを重複加算しない |
| 秒切上げの予備 | 一episode1秒 | 実際の端数ではなく計算上の保守枠 |

`GPU秒 = 出力token/出力TPS + 入力token/prefillTPS + 起動回数×(load＋idle＋切上げ枠)`。

入力と出力が完全には重ならず直列に処理される基準。batchの効果は実測前なので基準へ入れない。起動率10%やprefill1,000を変える感度に加え、**入力・起動・待機をすべてゼロにした楽観ケース**も別に出す。これにより、起動率の仮定だけが赤字判定を作っていないことを確かめられる。

短文試験のtoken/秒はprefillを含む生成区間から求めた値で、純decode速度の実測ではない。本計算の25TPSはそこを参照して別途置いた保守的な性能仮定であり、prefill1,000TPSとの時間内訳を実測分解したものではない。長文・最適化backendへの投影誤差も感度で扱い、本番実測へ昇格しない。

## 4. 有料50人・無料950人の月額

| 項目 | 基準案 |
|---|---:|
| 税込売上 | 42,000円 |
| 手取りの計画額（26%条件） | 27,262円 |
| GPU出力処理 | 596.69 GPU時間 |
| GPU入力処理の仮定 | 86.06 GPU時間 |
| 起動・待機・切上げ予備 | 78.98 GPU時間 |
| GPU合計 | 761.72 GPU時間 |
| GPU費 | 84,094円 |
| 共通基盤・保存・予備 | 11,000円 |
| **月額運用費試算** | **95,094円** |
| **手取り−運用費** | **−67,833円** |

一月720時間を超えるGPU時間は複数workerの合計であり、一台を761時間動かすという意味ではない。平均稼働率60%の計画余裕で2worker相当。worker上限4以内でも、時刻別ピーク・待ち時間・SLAが成立した証拠ではない。

上記差額は人件費・広告・返金・開発／学習費をまだ引いていない。手取りの20%を運営余力として残す案では、AIに使える額は10,809円までで、さらに不足する。運営余力20%はMash確定の利益率ではない。

**起動・入力・待機の費用がゼロでも**、25出力token/秒のままでは運用費76,874円、差額−49,613円。税込売上42,000円そのものも上回るため、手数料26%や20%余力だけが不成立の原因ではない。したがって、この参照性能と使用量では、Serverlessへ変えるだけでは解決しない。

## 5. 他の提供案と人数

下表は同じtoken量・参照性能を置いた試算。別GPUの搭載・速度は未検証であり、安価な実配備を確認した値ではない。

| 提供案 | 有料50人・基準負荷の月運用費 | 条件 |
|---|---:|---|
| Flex16GB | 81,688円 | 4B長文fit未検証 |
| **Flex24GB** | **95,094円** | 今回の計算基準 |
| Flex48GB A40群 | 159,689円 | 単価$1.22/h |
| 常時A5000 24GB | 73,208円 | $0.27/h、平均余裕60%で2台が必要な計算 |

常時案を「1台の料金」で安く見せず、全仕事を処理する計画台数へ増やしている。GPUサイズを半分にしても料金半減ではなく、Flex48→24は同じ課金時間なら約43.4%減、24→16は約15.9%減である。4B／9Bを同じGPU・token量・仮定性能へ置くと**費用は同額**。モデル名で割引しない。

基準の無料者が常に有料者の19倍になる条件で人数を増やすと、次になる。

| 有料／無料人数 | 手取り計画額 | Flex24基準案の運用費 | 差額 |
|---|---:|---:|---:|
| 10／190 | 5,452円 | 27,819円 | −22,367円 |
| 50／950 | 27,262円 | 95,094円 | −67,833円 |
| 100／1,900 | 54,524円 | 179,189円 | −124,665円 |
| 200／3,800 | 109,047円 | 347,378円 | −238,330円 |

200／500人では平均余裕を含む必要worker8／18となり、固定max4のままでは容量も不足。上表は要求を捨てて安くした額ではなく、全仕事を処理するなら必要なGPU時間の費用。さらに共通費を全規模11,000円で保持した楽観側の数字で、規模増額もあり得る。

この無料比率・単位負荷・参照性能を保つ限り、変動費が売上に勝つため、人数増加だけでは損益分岐に届かない。無料者が固定人数の場合や有料化率が変わる場合は別で、[results.json](results.json)へ有料化率5／10／20／100%の感度も残した。低／基準／高使用量0.5／1／2倍、手数料15／26%も別行に保存する。利用制限を変更した意味ではない。

## 6. 価格を維持する場合の必要条件

有料50／無料950の基準で、20%の運営余力を残すなら、GPU費10,809円以内、Flex24で**月97.91課金GPU時間以内、1名目生成あたり平均4.46課金GPU秒以内**が必要。基準試算は平均34.72秒で約7.8倍である。

起動・待機・入力処理がゼロだとしても必要な出力実効throughputは約152token/秒/GPU。これは最低限の必要条件で、達成しても他費用を足せば足りない。batch時は各要求の見かけの速度ではなく、GPU全体の処理token／課金秒で測る。

| 未測定の別性能構成 | 50人の月運用費 | 差額 | 算術上の損益分岐／20%余力まで |
|---|---:|---:|---|
| 合計100出力TPS・4,000入力TPS・起動率1% | 30,716円 | −3,454円 | 有料75人／265人 |
| 合計200出力TPS・8,000入力TPS・起動率1% | 21,294円 | ＋5,968円 | 有料35人／50人 |

これらは同時数4／8を仮定する**未実装・未測定の別構成**で、基準の同時数1と同じ本番性能ではない。64k Analysisは単独にし短要求をbatchできるか、長文・LoRAでメモリと品質を保てるかが未確認。200TPS案も20%余力後の残りは約515円しかなく、予備超過・為替・使用量の小変動で崩れる。価格成立の証拠として採用しない。

**今回の判断：固定した基準案は不採用。680／1,480円自体を値上げすべきと断定せず、維持するなら上記課金時間の予算内へ入る構成の実証が必要。** 現状の25TPSから未実測の200TPSへ、表の上だけで飛ばして黒字としない。追加学習・教材増量・価格／quota変更は今回行わない。
