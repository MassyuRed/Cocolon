## 2. 出力は本文で読む

全core共通：主語・対象・時点・肯否・条件・留保、関係の方向、根拠のない動機/他者内心/因果/人格の追加を読む。根拠IDの自己申告だけでは合格にしない。実際に指しているrecord/fieldの意味と照合する。

Emlis：観測・人間的な受け取り・問いの必要性・補足後の変化を読む。事実しかない入力に短く事実を受け取ることは成立し得る。一方、豊かな関係のある入力まで全部同じ言い換えと汎用共感へ潰す場合は不足。問い数を多くした方を上位にしない。Free/Plusはthread全体1問、Premiumは本人続行による最大3問。今回の単発snapshot指示は最大1問なので、Premiumの3往復を検証したことにはならない。

Piece：原入力を見ない読者が「誰の何についての考えで、何が決まり/未確定か」を説明できるかを見て、その後sourceへ照合する。本人の声と単独伝達性、核・留保を保つ文章構成を読む。原文をそのまま貼るだけを文章形成成功にせず、意味を削る短縮や宣言化も成功にしない。recipe/fit/実bitmap/画像保存/共有は別の実行証拠で、本文試験だけでは未検証。

Analysis：文章とnode/edgeが同じ意味を持ち、根拠のある部分だけで読みやすいかを見る。明示した役割は保持し、役割のないA01へ人格ラベルを作らない。edgeは明示順序/共起/因果を分ける。期間内の別記録を一本の出来事へ連結しない。こころ天気の集計は既存の数値処理で、モデルが推定した気持ちへ置き換えない。A01のweak1/medium2集計を補助確認するならP0＝不安3/悲しみ1/平穏2、P1＝平穏5/喜び1/不安1。これを状態改善の証拠へ変換しない。

IF：本人側の異なる選択肢が成立するかを見る。例として「希望を伝える」「今回は予定通り動き見たかった箇所を残す」「時刻は変えず気持ちだけ伝える」等があり得るが、文言一致は求めない。他者の意図/反応/関係の結末とhealth/medicalは対象外。仮想と書けば他者の反応を自由に予測してよいという意味ではない。

SavedRouteIntent：実際に生成された候補IDと架空本人の明示選択・メモ・保存時刻を、観測/仮想候補とは別identityに束縛する。本人の意向に合う候補がなければ未選択のままにし、候補IDを捏造しない。選択は行動の実施/達成/失敗や、次期記録への効果の証明ではない。この確認は将来の保存接続で行うもので、今回モデルへの追加生成要求は0。現runtime未実装を保持する。

## 3. 比較記録の最小形

一つの結果表へ次の欄を作り、source本文・生成本文は対応する行から辿れる形で保存する。今回は空の評価結果を大量作成しない。

`case_id / family / split / condition / repo_ref・model_identity / visible_input / actual_prompt・settings / actual_status・reason / full_output / evidence_check / meaning_preservation / uncertainty / naturalness・usability / core_task / update_or_NA / major_errors / elapsed・tokens / reviewer / next_action`

statusはNOT_RUN、UNAVAILABLE、NOT_IMPLEMENTED、INFRA_ERROR、TRUNCATED、OUTPUT_AVAILABLE等の実事実を使う。native未対応の行を黙って除外せず、両条件で本文がある共通部分と、全体の出力可能範囲を分けて示す。不足情報に適切に限定した出力と、能力不足で本文が作れなかった失敗を同一にしない。

意味保持/不明の扱い/自然さと有用性/core目的について、華恋の診断メモとして0＝重大不足、1＝部分成立、2＝この場面で明白な不足なし、N/A＝対象外を使える。根拠とactual本文を必ず添える。合計点や平均で採否を自動決定しない。採点者を「独立した人間」と偽らず、華恋/別agent/Mashの誰が読んだかを残す。モデルの自己採点をhuman Product Readにしない。

この少数fixtureの診断が良くても、未知入力全般・商品需要・追加学習成功・三中核の本統合・アプリ完成の合格へ拡張しない。華恋が明白な不足を先に確認し、Mashへ低品質な本文の判定負担を戻さない。Mashの最終品質判断は別の事実として残す。
