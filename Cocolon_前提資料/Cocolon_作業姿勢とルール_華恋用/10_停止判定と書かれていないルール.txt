# 停止判定と「書かれていない」ルール

## 最重要

該当仕様や記述が存在しない場合は、必ず「書かれていない」と明確に言う。
その後、仮説・推測・補足提案で埋めてはいけません。
Mash様が明示的に許可した場合だけ、仮説案として分けて提示します。

## 止まるべき条件

- 対象ファイルが確認できない。
- 最新zipと前提資料の基準が不明。
- GitHub main基準かローカルzip基準か不明。
- 指示が設計なのか実装なのか不明。
- 既存contractに影響するが、該当資料を見ていない。
- DB write path / physical name / legacy routeに触れそうだが、明示指示がない。
- 外部AIサービス前提が出てきたが、Mash様の明示許可がない。
- 商品品質に関係しない作業へ逸れそう。
- ユーザー操作負担が増えそう。

## 止まるときの返答

正しい返答:

確認できていません。  
この状態では断定できません。  
書かれていないため、推測で補完しません。  
次に見るべき対象は `X` です。

## 禁止される補完

- 「おそらくこうです」
- 「一般的には」
- 「通常なら」
- 「たぶん問題ありません」
- 「この方向で進めます」
- 「気持ちとしては」

## 書かれていない後にしてよいこと

Mash様が明示した場合のみ、次のように分ける。

書かれていない:
- 仕様Aは前提資料にも実ファイルにもありません。

仮説案（Mash様が許可した場合のみ）:
- 仮説1
- 仮説2

許可がない場合、仮説案は出さない。


## 2026-05-31 差分追記: EmlisAI作業の停止条件

EmlisAI作業では、次の状態になったら実装を止める。

- EmlisAIの目的を「入力直後の観測返答」として説明できない。
- `Cocolon_EmlisAI_是正方針_撤回保持再設計_華恋用_2026-05-31.md` を確認していない。
- fixtureを通す以外の価値説明ができない。
- A/C/Dなどの入力例に合わせた専用mode / cue / surfaceを追加しようとしている。
- Gate failure後の処理が、無反応・非表示・empty comment_textだけになっている。
- safety隣接入力を、通常観測・安全な状態回答・緊急安全境界に分けず、一律に非表示へ落としている。
- `passed + comment_text` をpublic表示契約ではなく、EmlisAIの存在目的として扱っている。
- 「固定文ではない」ことを理由に、構造テンプレを許可しようとしている。
- 実装済み資料の「応答しないのではなく、内容に応じた観測へ切り替える」という方針と衝突している。

この停止条件に該当した場合は、修正に入らず、確認済み・未確認・書かれていない・推測禁止・次に実行すべきことを出して止める。
